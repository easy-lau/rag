# UI 开发规范

> 适用范围：`frontend/` 下所有新增或修改的页面、组件、弹窗、下拉、表格和移动端交互。
> **开始任何 UI 开发前，必须先阅读本文，并优先复用现有的全局主题与 `components/ui/` 组件。**

## 1. 目标与原则

- 保持问答工作台、管理后台和登录页属于同一套企业工作台设计语言。
- 先复用全局 token、Naive UI Theme 和共享组件；禁止为单个页面重新发明一套圆角、阴影、按钮或弹窗。
- 视觉层级由语义决定：颜色只表达品牌、状态和风险，不能只为装饰而大量使用。
- 所有看起来可点击的元素必须真实可用；所有不可逆操作必须有一致的二次确认。

## 2. 开发前必做检查

1. 阅读本文。
2. 检查 `src/styles/tokens.css`、`src/theme/naive.js` 和 `src/components/ui/` 是否已有可复用实现。
3. 确认页面属于工作台、后台还是认证页，并复用对应布局与页面骨架。
4. 同时考虑浅色、深色、360 / 768 / 1024 / 1440px 宽度，以及键盘操作。
5. 若确需新增视觉规则，先扩充 token 或共享组件；不要在业务页面散落硬编码色值和 `!important`。

## 3. 设计 token 与尺度

Token 是唯一视觉来源，名称和实际值以 `src/styles/tokens.css` 为准。新代码应使用 token 或 Naive UI 的全局 Theme，不要复制颜色值。

| 元素 | 标准 |
| --- | --- |
| 输入框、普通按钮、行内操作 | 10px 圆角 |
| 下拉菜单、Popover | 12px 圆角 |
| 卡片、标准 Modal / Dialog | 16px 圆角 |
| 欢迎卡、危险确认 | 20px 圆角 |
| Tag、状态胶囊 | 全圆角 |
| 普通控件高度 | 36px；紧凑操作可为 32px |
| 主内容最大宽度 | 以布局组件定义为准，聊天消息和输入框必须共用同一对齐线 |

- 普通正文与辅助文字应保持足够对比度；`text-gray-400` 只用于禁用、占位或极弱次要信息。
- 阴影只用于可浮起的层级（菜单、弹窗、强调按钮），卡片不应依赖重阴影堆叠。
- 深色模式必须使用同一语义 token，不能只替换局部背景色。

## 4. 组件选择规则

### 按钮与行操作

- 主页面每个操作区最多一个 Primary Button；其他操作使用 secondary 或 ghost。
- 图标按钮必须有 `aria-label` 和 Tooltip；不可只依赖颜色传达含义。
- 表格中的名称、对象、摘要左对齐；状态、数值、时间和短操作居中。
- 可破坏操作使用统一危险样式，不能与普通文字操作同权重并列。

### Modal、Drawer、Popover 与 Select

- 新建表单、编辑表单、预览和危险确认优先使用 `AppModal` / `DangerConfirm` 等共享组件。
- 不新增裸 `n-modal preset="card"`、默认 `n-popconfirm` 或 `dialog.warning` 作为永久删除确认。
- 所有永久删除都必须显示对象名称或数量、不可恢复提示、红色确认按钮；提交中禁止关闭或重复提交。
- Drawer 必须有可见标题和关闭按钮，不能只依赖点击遮罩关闭。
- 浮层挂载与样式必须遵从全局 Theme / `#app` 策略，禁止用 Teleport 后失效的局部 Tailwind 规则补救。

### 表单与下拉

- 标签在上、帮助文本在下；错误提示应靠近字段。
- Select / Dropdown 打开后，触发器应有明确 active 状态。
- 只读权限下，字段、上传、清除和保存入口必须一致地禁用，并说明“当前仅查看”。

## 5. 响应式规则

| 区间 | 规则 |
| --- | --- |
| `< 640px` | 手机：触控目标不小于 40px；复杂筛选收进 Drawer / Popover；避免隐藏横向滚动提示。 |
| `640–1023px` | 紧凑/平板：侧栏使用 Drawer；表格仅保留核心列或提供详情；禁止同时固定左右双栏。 |
| `1024–1279px` | 桌面紧凑：后台可显示侧栏，聊天检索结果使用 Drawer。 |
| `>= 1280px` | 宽屏：聊天左栏和检索结果栏可以同时常驻。 |

- 不要只依赖 viewport 推断实际内容区宽度；侧栏、结果栏和弹窗都会压缩容器。
- 文档编辑器等双栏界面在紧凑屏必须切换为单栏 + “编辑 / 预览”切换。
- 所有 Markdown 图片、长代码和表格必须避免撑破消息或预览容器。

## 6. 可访问性与交互真实性

- 交互元素使用原生 `button` 或具备等价键盘语义；不可用没有 `href` 的 `<a>` 充当按钮。
- 支持 Tab 焦点、Esc 关闭浮层、关闭后的焦点恢复；明确 `focus-visible` 样式。
- 仅在真实存在处理逻辑时显示“查看更多”“重新生成”“点击预览”等操作。
- 颜色不能是状态的唯一表达；加载、成功、失败、检索过程需有可读文字。
- 为动画提供 `prefers-reduced-motion` 降级。

## 7. 页面与代码组织

- 后台页面使用统一的 `PageHeader + SurfaceCard / DataTable` 骨架；顶栏只提供全局上下文和账户操作。
- 问答工作台中，会话侧栏负责“新对话”和历史管理；当前会话标题、检索结果等会话级工具放在 `AppHeader`，消息区不再重复设置工具栏。
- 共享 UI 放在 `src/components/ui/`；业务组件只保留业务数据、事件和页面特有布局。
- 新增全局颜色、圆角、阴影、断点时，先修改 token / theme，再在业务组件中使用。
- 删除或替换旧布局前，先确认路由和引用；避免让旧 UI 重新进入路由链路。

# RBAC 权限模型规范

> 适用范围：用户、角色、权限目录、菜单路由、知识库范围以及所有需要登录的业务接口。

## 1. 模型边界

系统采用“一名用户对应一个角色”的 RBAC 模型：

```text
用户
  └─ 角色
      ├─ 功能能力 permissions
      └─ 知识库范围 scope_mode + role_knowledge_bases

菜单入口由功能能力派生，不作为独立的安全授权项。
```

- `is_superadmin=true` 是应急超级管理员，只保留极少数账号并绕过普通角色校验。
- 普通角色只能获得权限目录内声明的能力，禁止保存未知权限 key。
- 当前保持单角色，不增加多角色叠加和用户直接授权。

## 2. 功能能力

- 权限 key 使用 `资源:动作` 格式，例如 `doc:read`、`intent:manage`。
- 后端权限目录是权限名称、说明、风险等级、依赖关系和 `superadmin_only` 委派限制的唯一来源，前端不得维护另一套安全规则；前端兼容旧目录的兜底值不能作为后端授权依据。
- 写能力按动作拆分，不能用一个“编辑”权限同时代表新增、修改和删除。
- 知识库写能力 `kb:create`、`kb:update`、`kb:delete` 都自动补齐 `kb:read`；文档写能力 `doc:create`、`doc:update`、`doc:delete` 都自动补齐 `doc:read` 和 `kb:read`，但写动作之间互不依赖。
- `menu:*` 只作为登录响应中的派生入口兼容值，不写入新角色授权。
- `log:read` 同时派生“审计日志”和“调用链路”两个只读菜单；两个接口都必须由后端再次校验 `log:read`。生产环境指标型调用链可由审计员查看；临时开启正文追踪后，含业务正文的详情与导出额外限制为超级管理员，普通审计员列表中也看不到问题/回答摘要。
- 前端按钮和路由可以根据有效权限隐藏，但所有写接口必须通过后端 `require_permission` 或对象范围依赖强制校验。

知识库与文档采用以下操作权限：

| 资源 | 查看 | 新增 | 修改 | 删除 |
| --- | --- | --- | --- | --- |
| 知识库 | `kb:read` | `kb:create` | `kb:update` | `kb:delete` |
| 文档 | `doc:read` | `doc:create` | `doc:update` | `doc:delete` |

`kb:write`、`doc:write` 是废弃的历史 key，只用于迁移读取兼容和缓存旧前端的响应别名。只有可无损映射回旧模型的完整动作组合才会派生别名；当前后端接口不使用别名鉴权，角色新建和编辑接口也必须拒绝保存它们。

## 3. 知识库数据范围

角色的数据范围只能取以下一种：

| `scope_mode` | 语义 | `kb_ids` |
| --- | --- | --- |
| `none` | 不访问知识库 | 必须为空 |
| `selected` | 只访问指定知识库 | 至少一个有效知识库 ID |
| `all` | 当前及未来全部知识库 | 必须为空 |

- 数据范围不是功能权限；拥有 `selected` 范围不代表可以读取或修改文档。
- 文档、检索、问答和知识库对象操作必须先校验能力，再校验目标 `kb_id` 是否在范围内。
- 上传的文档原图同样属于知识库数据，必须通过携带 Token 的受保护接口读取；只有登录页品牌图片可以公开静态访问。
- 创建知识库没有既有对象可供范围校验：普通角色只有在同时具备 `kb:create` 和 `scope_mode=all` 时才是有效配置；超级管理员仍可直接执行。

## 4. 授权上限

### 文档对象所有权

文档写操作在功能能力和知识库范围之外，还必须校验对象所有权：

```text
修改正文、标题、标签或启停状态：doc:update + 知识库范围 + 文档创建者
删除文档：doc:delete + 知识库范围 + 文档创建者
```

- `is_superadmin=true` 可以管理任意知识库中的任意文档，普通角色名称不能作为管理员判断依据。
- `created_by IS NULL` 的无主文档只有超级管理员可以修改或删除，普通用户不能自动认领。
- 管理员修改文档只更新 `updated_by`，不得隐式改变 `created_by`；所有权转移如需支持，必须设计为独立且可审计的高风险操作。
- 正文、标题、标签、启停、删除、批量操作以及后续新增的文档写入口必须复用同一对象授权策略，禁止在各接口复制判断。
- 文档响应由后端返回逐对象操作能力供前端呈现；前端不得根据用户名、创建人名称或角色名称重建授权规则，且不能替代后端校验。
- 越权写操作返回 403，并记录操作者、文档、所有者、请求动作和拒绝原因。

- 非超级管理员不能编辑自己的角色、系统角色或包含高风险身份能力的角色。
- 授权者不能授予自己没有的能力，也不能授予超过自身的数据范围。
- `role:manage`、`user:manage`、`settings:write`、`kb:create`、`kb:update`、`kb:delete` 和全部知识库范围属于高影响授权；在完整的分级委派能力建立前，只允许超级管理员授予。
- 超级管理员角色不可分配给普通账号；普通管理员不能修改、禁用或删除超级管理员。
- 系统角色不可删除，角色仍有用户时不可删除。

## 5. 内置角色模板

推荐从模板创建角色，再按最小权限调整：

- 普通问答用户：智能问答，可选指定知识库。
- 知识库阅览者：知识库和文档只读，指定知识库。
- 知识编辑者：文档读取、新增和修改，指定知识库；默认不含 `doc:delete`，删除必须显式授权。
- 检索分析员：知识库读取、文档读取和检索测试。
- 智能路由运营员：智能路由读取和管理，不需要知识库范围。
- 审计员：只读登录日志和操作日志。
- 平台管理员：系统设置与审计，高风险模板只允许超级管理员使用。

## 6. 新增权限检查清单

- [ ] 权限已加入后端目录并提供中文名称、说明、风险和依赖。
- [ ] API 已做后端能力校验，不能只隐藏前端按钮。
- [ ] 涉及知识库对象时已校验 `kb_id` 数据范围。
- [ ] 文档写接口已通过共享策略校验创建者或超级管理员，前端逐对象能力与该策略来自同一后端决定。
- [ ] 菜单派生规则与路由守卫已同步。
- [ ] 角色管理页可展示并正确解释该能力。
- [ ] 高风险操作有审计日志和必要的二次确认。
- [ ] 迁移兼容已有角色，未知或废弃 key 不会被静默转成更高权限。
- [ ] 后端测试、前端构建和 `git diff --check` 通过。

## 7. 迁移与部署

- `0019` 同时修改数据库角色结构和应用读取逻辑，不支持 0018 / 0019 新旧实例混合运行。
- `0020` 将历史 `doc:write` 等价迁移为文档新增、修改、删除三项；历史 `kb:write` 在 `all` 范围迁为三项，在 `selected` 范围只迁修改和删除，以保持旧版“指定范围不能新建知识库”的有效行为。
- `0020` 回滚仅接受可无损还原的组合：文档必须同时拥有三项写动作，全部知识库范围必须同时拥有知识库三项写动作，指定范围必须同时拥有知识库修改和删除。存在其他部分组合时迁移会明确终止，必须先规范角色或恢复迁移前备份，禁止静默扩大权限。
- 生产部署前先备份数据库并停止旧应用，再执行 `alembic upgrade head`，确认迁移成功后启动新版本。
- 迁移后重点核对超级管理员角色不可分配、普通用户角色的指定知识库范围，以及历史自定义角色是否仍符合最小权限。
- 回滚只能恢复旧版本运行所需的有效权限语义，不能精确还原已经废弃的冗余菜单授权行；生产回滚优先使用迁移前数据库备份。
